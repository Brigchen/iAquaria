# iAqua 手机 App（Android）产品与开发方案

版本：v1.0（2026-09-14）　定位：水族缸智能管理中枢　平台：Android

---

## 1. 定位与功能边界

| 端 | 定位 | 一句话 |
|---|---|---|
| Web 仪表盘 | **实时控制台** | 同网段直连设备，看数据、控制执行器、调参数 |
| PC 上位机 | **记录工作站** | 长期记录 SQLite、导出 CSV、曲线分析 |
| **手机 App** | **管理中枢** | 多缸档案、养护日志与计划、智能提醒，随时随地掌握状态 |

App **不重复做**实时控制（保留 Web），主打三件差异化的事：
1. **多缸管理**——一个 App 管多个缸（客厅缸、阳台缸…），一键切换
2. **养护闭环**——日志记录 + 周期计划 + 完成打卡
3. **智能提醒**——阈值告警 + 周期任务提醒 + 基于数据的操作建议

## 4. 功能规格

### 4.1 多缸管理（Tab4 + 顶部切换器）
- 缸档案：名称、位置、容量 L、水型（淡水/海水/草缸）、建缸日期、运行天数（自动计算）
- 每缸绑定设备：主板 WS 地址（`ws://<ip>/ws`）+ 摄像头基地址（复用 `cam.url` 逻辑）
- 生物/水草/设备清单：条目化记录（名称、数量、入缸日期、备注、照片）
- 切换器行为：顶部下拉切换，全部 Tab 数据随缸切换；支持缸归档（不动数据）

### 4.2 监测数据（Tab1 概览 + 数据详情页）
- 实时卡片：8 指标同 Web（水温/pH/ORP/TDS×2/光照/485温/水位），离线指标置灰
- 摄像头画面：MJPEG 流直嵌（`:81/stream`），不支持流的场景自动降级 `/capture` 快照轮询（与 Web 端同策略）
- 历史趋势：复用设备 `{"cmd":"hist","hours":24|168|720|8760}` 协议，曲线归一化 + 图例区间显示（对齐 Web 端既定规则）
- 数据详情页：单指标全屏曲线 + 统计（min/max/均值）+ 关联日志锚点

### 4.3 养护日志（Tab2）
- 时间线视图，按天分组，按类型筛选：水质检测/换水/喂食/维护/其他
- 记录条目：类型 + 数值备注（如换水 30%、GH6·KH8）+ 照片（≤9 张）+ 时间
- 部分记录**自动生成**：设备投喂、手动开关执行器、告警事件自动写入日志（区分“自动/手动”徽标）
- 悬浮 [+记录] 快捷入口，2 步内完成一条记录

### 4.4 计划任务（Tab3）
- 周期任务模板：喂食（每日 n 次）、换水（每 n 天）、滤材清洗、水质检测、设备保养
- 分组：今天 / 即将到期（3 天内）/ 已逾期，逾期置顶高亮（对齐范例）
- 一键完成：完成任务 → 自动写入日志（含实际完成时间）→ 下周期顺延
- 任务可暂停、改周期、单次跳过

### 4.5 智能提醒（核心差异化，详见 §5）
- 三类提醒统一进系统通知栏 + App 内提醒中心（概览页横幅 + 未读角标）

### 4.6 数据与导出（Tab4 内）
- PDF 报告：选择时间范围 → 趋势图 + 统计 + 日志摘要，可打印
- CSV 导出：原始读数（列格式对齐 PC 上位机 `iaqua_export.csv`，便于合并分析）
- 备份与恢复：缸档案 + 日志 + 计划 + 提醒规则打包 zip 本地备份；二期加 WebDAV 云备

## 5. 智能提醒引擎

三层规则，全部按缸独立配置，**阈值区间、持续确认次数、冷却时间、免打扰起止时段与静默范围均可在 App 内自定义**（交互原型见 docs/app_prototype.html 第 16–17 屏），规则用 JSON 描述（可导入导出分享）：

### 5.1 阈值告警（实时层）
| 规则要素 | 说明 |
|---|---|
| 指标 | temp/ph/orp/tds1(滤前)/tds2(滤后)/lux/lvl（tds1/tds2 为协议键，显示名 TDS(滤前)/TDS(滤后)） |
| 触发 | 越上/下限 **持续 N 个周期**（默认 3 次 tel 帧去抖） |
| 恢复 | 回到限值内持续 5 周期 → 自动消除并记日志 |
| 静默 | 免打扰时段（如夜间只静默"光照"类）；同规则冷却 30min 防轰炸 |

默认规则（开箱即用）：水温 24~28℃、pH 6.4~7.6、TDS 超基线 ±30%、水位 <20% 或 >95%。
基线取该缸近 7 天中位数，用户可改固定值。

### 5.2 周期任务提醒（计划层）
- 到期前 1h + 逾期时各推一次；由计划模块驱动（§4.4）

### 5.3 操作建议（智能层，趋势/组合规则）
| 触发条件（示例） | 建议文案 |
|---|---|
| TDS 连 7 天单边上升 | "水质老化趋势，建议本周换水 20~30%" |
| pH 昼夜差 >0.6 | "CO2 波动可能过大，检查电磁阀联动与气泡数" |
| 加热棒单次连续运行 > max_on_min×80% | "加热效率下降，检查加热棒或保温" |
| 水位 72h 内下降 >5% | "蒸发加快/疑似渗漏，建议补水并检查" |
| 光照峰值连续 3 天 < 昨日 50% | "灯具衰减或遮挡，检查灯光" |
| 设备/摄像头离线 | "设备失联，检查电源与 WiFi" |
| 换水后 TDS 骤降 >25% | "换水量可能过大，注意生物应激" |

实现：一期在 App 端规则引擎（本地评估 tel 流 + hist 数据）；二期规则可上移服务端（云中转阶段），App 仅收推送。

## 6. 技术方案

### 6.1 技术选型（推荐）
| 项 | 选型 | 理由 |
|---|---|---|
| 语言/UI | Kotlin + Jetpack Compose | Android-only 定位，原生后台/推送能力最强，Material3 圆角卡片风格契合范例 |
| 本地存储 | Room（SQLite） | 日志/计划/读数缓存；便于 CSV 导出 |
| 网络 | OkHttp WebSocket + 自研 MJPEG 解析组件 | 直接复用现有 WS 协议 |
| 依赖注入/异步 | Hilt + Coroutines/Flow | tel 帧流天然适配 Flow |
| 图表 | 自绘 Canvas 或 Vico | 需归一化多曲线 + 时间轴，定制量小 |

> 备选：Flutter（若未来要 iOS）。但推送与后台保活在 Flutter 需更多插件拼装，一期不建议。

### 6.2 连接架构（分两期）
```
一期（局域网直连，无服务器）           二期（云中转，跨网+离线推送）
┌──────┐  WS   ┌─────────┐          ┌──────┐ MQTT ┌─────┐ MQTT ┌─────┐
│ App  │──────▶│ iAqua主板│          │ 主板 │─────▶│ 云   │◀────▶│ App │
└──────┘  HTTP │ 摄像头节点│          └──────┘      │Broker│      │+推送 │
   │          └─────────┘                        └─────┘      └─────┘
   └─同网段直连 :80/:81                     厂商推送通道(小米/华为/荣耀/FCM)
```
- **一期**：App 在同网段直连设备，解析协议与 Web 端完全一致（`hello/tel/cfg/hist/log/ack`），零固件改动；前台服务（常驻通知）维持 WS 接收并跑阈值引擎
- **二期**：固件增加 MQTT 上报（每 30s 快照 + 事件即报）→ 云 Broker（EMQX 自建/阿里云）→ App 订阅；告警判定移到服务端规则引擎，经厂商推送通道触达**离线手机**；App 内也可远程下发控制（扩展 `ctrl/feed` 指令走云端）

### 6.3 关键技术点
| 难点 | 方案 |
|---|---|
| Android 后台保活 | 前台服务（类型 connectedDevice）+ WorkManager 兜底重连；一期明确告知"局域网提醒需 App 后台存活" |
| MJPEG 解码 | 自研 multipart 解析 → BitmapFactory，复用单帧到 TextureView；摄像头固件已支持 3 客户端并发 |
| 多设备并发连接 | 每缸一条 WS 连接按需挂/断：前台缸保持连接，后台缸 60s 轮询一次快照 |
| 设备安全 | 一期为局域网明文（与现状一致）；二期云端加 token + TLS |

### 6.4 数据模型（Room 核心表）
```

livestock(id, tank_id, kind[生物|水草|设备], name, count, since, note, photo)

```

## 7. 里程碑规划

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| **M1 MVP（局域网）** | 多缸管理、概览实时卡、历史趋势、日志、计划、阈值告警（本地通知） | 手机与 PC 同时看同一缸数据不冲突；断网提醒正常 |
| **M2 完整** | 摄像头画面、建议引擎、图文日志完善、PDF/CSV/备份 | 范例图 4 张对应页面全部可用 |
| **M3 云端** | 固件 MQTT 上报、云 Broker、服务端规则引擎、厂商离线推送、远程控制 | 外网 4G 下收到告警 ≤30s |

依赖与风险：
- M3 需固件加 MQTT（`PubSubClient`，ESP32 资源占用约 20KB 堆）
- 国内厂商推送需各开发者平台入驻（个人账号可小米/荣耀，华为需企业）；可先用自建 MQTT 常驻连接过渡
- 多缸数量建议 ≤10（每缸一条 WS 连接的内存与电量权衡）
